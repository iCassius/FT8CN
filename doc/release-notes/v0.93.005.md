## 功能与稳定性改进

- 配置加载改为明确的“逐项读取 + 完成通知”状态模型；旋转、重建和损坏配置值不会把未完成加载当作可用状态。
- 发射流程由统一 PTT/SCO 协调器管理，断开连接、停止和延迟回调会安全收尾，避免生命周期切换中重复或遗漏恢复动作。
- 网络电台与音频任务使用有界串行队列、提交快照和会话 generation 隔离；TCP/UDP EOF、断线与旧回调不会污染新的连接状态。
- FT8 解码改为单飞协调和 epoch 生命周期隔离；重叠时隙跳过，空结果、异常和取消都有统一终态，旧解码结果不能污染新周期。
- 修复解码回调在入口 epoch 检查后被 `onCleared()`/停止插入的竞态：消息列表/UI、关注列表、QTH、自动回复解析和数据库持久化现在都要通过短门控准入；停止先关闭门控，再取消可能仍在返回的解码任务。
- 修复解码 Future 在真正启动前被取消时残留 `active=true` 的问题；运行中的旧 Future 不会清理新任务状态。
- 修复解码耗时发布在取消检查后仍可更新 `timeSec`/`decodeTimeSec` 的生命周期竞态；耗时 UI 现在也必须通过当前 epoch 门控准入。
- 录音启动改为 session/generation 隔离的异步初始化；权限、`AudioRecord` 构造/启动异常和停止都统一清理各自服务与资源，旧 session 不会误停新 session。
- 收口录音会话交付竞态：`MicRecorder` 为每个 session 捕获独立回调和浮点缓冲，并以 session identity/lease 在交付点准入；`HamRecorder` 将 monitor 绑定 recorder generation，停止和清理走单一终态，旧音频、强制结算和解码回调不能进入新 session。
- 前台录音服务增加严格 session/startId 状态机和 `ResultReceiver` ACK；stale STOP 不会误停新 session，无 active session 时可靠自停，`startForeground` 失败会清理服务并向启动方返回失败真值。
- `MainViewModel` 与 `UtcTimer` 的 heartbeat 使用 cleared/epoch fence；补充正常 duration publication、heartbeat、服务生命周期、录音交错和 monitor 异常传播测试。
- 新增真实逻辑层录音失败清理 instrumentation，并用 `Future`、executor、latch 强制交错验证解码门控和旧 `finally` 不清理新任务。
- 录音启动真值、Yaesu/FT-710 生命周期、Wavelog station ID 精确匹配和 JTDX priority 前置计算已修复；异步归属地刷新不重复计算 priority/会话统计。
- 保持 Android `minSdk 23`，修复发射任务集合的 API 兼容性；补齐希腊语、日语和西班牙语的新增界面字符串。
- 保留本地 TXT/ADIF `file/content` 导入 intent filter，并仅对该非 Web filter 做精准 `AppLinkUrlError` suppression。
