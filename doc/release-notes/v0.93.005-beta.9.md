## Beta 发布前置顺序

beta.9 只能在以下顺序全部满足后创建 annotated tag：

1. 将最终候选 HEAD 推送到新的集成分支。
2. 以 fast-forward 方式把 `origin/codex/v0.93.005-integration` 更新到完全相同的 HEAD；不得用 16KB 分支替代 canonical integration，也不得 force-push。
3. 用远端 peeled commit 核对 `v0.93.005-beta.9` tag 目标与 `origin/codex/v0.93.005-integration` 精确相等；tag 创建并推送动作不属于本说明的授权范围。
4. GitHub Actions 还必须核对 beta.9 的版本、notes、beta-only certificate、zipalign、四 ABI、JNI/ELF/16KB gate、JVM 和 APK metadata；任一门禁失败都不得创建或修改 Release。

正式 Release 仍为 `NO-GO`：本地没有受保护的 formal keystore、可信正式证书材料和正式发布批准。
